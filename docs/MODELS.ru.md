# Модели по этапам: что можно подключить, цена и качество

Цены сверены со страницами провайдеров 12.09.2026: Anthropic, OpenAI, Google AI, fal.ai. Оценка качества «для нашей задачи» (игрушечный 3D-мультяшный стиль, следование референсам, консистентность персонажей, отсутствие текста) экспертная, по опыту с похожими пайплайнами, а не замер. Замер даёт команда `node scripts/compare.mjs` на одном плане.

Актуальный каталог с ценами хранится в `models.json`, посмотреть: `node scripts/models.mjs`.

- Бесплатного API-тира для картинок нет ни у одного провайдера. Бесплатно только ручной режим и локальная генерация при наличии GPU.
- Если коллекций будет много, окупается обучение LoRA на своих 160 карточках: стиль перестаёт зависеть от промпта, а картинка стоит электричество.

## Как переключать модели

Три уровня, каждый следующий перекрывает предыдущий:

1. **`config.json`** в корне: модель по умолчанию для каждого этапа.
2. **Переменные окружения** `CARDGEN_PLANNER_PROVIDER`, `CARDGEN_IMAGE_MODEL` и т.п. или **флаги** `--provider` и `--model` у скриптов `scripts/plan.mjs`, `backends/*.mjs`, `scripts/qa.mjs`.
3. **Пожелания продюсера** в команде `/card-set`: фразы вроде «картинки через Gemini Pro, проверку через GPT» скилл превращает во флаги и пишет выбранные модели в отчёт.

Сравнить генераторы на одном плане:

```bash
node scripts/compare.mjs --plan examples/summer_coolness_remake.plan.json --backends openai,gemini:gemini-3-pro-image --cards 1,3,7,10
```

Результат в `out/compare/<коллекция>_<сет>/index.html`: строка на карту, колонки «оригинал» и по одной на модель.

Какая модель делала каждый этап, записывается в `plan.json` (`meta.planner`), `manifest.json` (`backend`, `model`) и `qa.json` (`judge`), чтобы результат можно было воспроизвести.
